# MTG Online Table

一个网页端万智牌自由对战桌原型。程序维护牌库、手牌、战场、墓地、放逐区、生命和法术力池；不内置规则判定，操作合法性由双方玩家自行确认。

## 使用方式

启动本地服务后访问：

```bash
python3 server.py
```

然后打开 `http://127.0.0.1:5173/`。

为了模拟双方同步：

1. 打开两个浏览器标签页。
2. 在大厅创建一张牌桌，或输入牌桌号加入已有牌桌；密码可以留空。
3. 在大厅选择以 P1、P2 或旁观身份加入；需要时可填写显示名。
4. 任一方操作后，另一个标签会通过浏览器本地通道和服务端状态轮询自动同步。

如果要让不在同一台电脑上的玩家加入，需要让对方访问运行 `server.py` 的这台机器：

- 同一局域网内可访问 `http://主机局域网IPv4:5173/` 或 `http://[主机IPv6地址]:5173/`。
- 运行服务的机器自己可以用 `http://127.0.0.1:5173/` 或 `http://[::1]:5173/`；其他设备必须使用运行服务机器的局域网地址，例如 `http://192.168.x.x:5173/`。
- 不在同一局域网时，需要使用端口转发、VPN，或 ngrok / Cloudflare Tunnel 这类隧道工具，把本机的 `5173` 端口暴露出去。
- 当前实现没有身份校验，拿到地址和牌桌密码的人都能加入并操作对应牌桌。

## 分发

分发压缩包需要包含这些文件：

- `index.html`
- `src/`
- `styles/`
- `server.py`
- `README.md`

解压后在目录内运行 `python3 server.py` 即可启动。

## 文件结构

前端不需要构建工具，`index.html` 会直接按顺序加载拆分后的脚本和样式。

```text
src/
  constants.js       常量、机制库、翻译词典
  sync-lobby.js      大厅、牌桌同步、心跳、重连
  state.js           初始状态、迁移、规范化、本地缓存
  render.js          主牌桌、状态卡、手牌、战场和卡面渲染
  actions-drag.js    玩家操作、拖拽、横置、标记、衍生物
  zones-cards.js     牌区弹窗、牌区移动、牌表导入、Scryfall 查询
  lookup-init.js     查询工具、日志、入口事件绑定

styles/
  base.css           全局变量、基础元素
  lobby.css          大厅
  topbar.css         顶部控制栏、查询面板
  panels.css         玩家状态卡、法术力、区域按钮
  table.css          战场、手牌、标记工具栏
  cards.css          卡牌、卡背、翻转动画
  dialogs.css        牌区、大图、置入牌库弹窗
  responsive.css     小屏幕适配
```

## 当前功能

- 大厅多牌桌同步：进入牌桌前需要创建或选择牌桌；每张牌桌有独立状态，牌桌号可查询，密码可为空。
- 无身份校验、无作弊防护，完全信任玩家。
- 本机浏览器会记录最近进入过的牌桌，并在大厅中给仍在进行的牌桌显示“上次游玩”标识，方便断线后重新加入。
- 当牌桌没有任何连接且 5 分钟没有新的操作或心跳后，服务端会自动清理这张牌桌。
- 双方牌桌动态同步。
- 顶部控制区包含连接状态、同步计时器、硬币/D6/D20 随机工具、查询工具和同步聊天。普通查询会先命中本地机制库，未命中再查询卡片；需要本地术语翻译时可输入 `翻译: trample` 或 `translate: trample`。
- 双方共享一个大战场，中线分隔双方半场；对手半场会按面对面视角倒置显示。
- 自己和对手状态栏是浮在战场上方的折叠卡片：标题栏可拖动，位置只保存在当前浏览器标签页，不会同步给对手；自己的手牌围绕中间战场展示，对手手牌和区域放在对手状态栏中查看。旁观身份会显示双方完整手牌和区域信息，但不能操作牌。
- 身份加入和顶部视角切换会写入同步日志，便于双方看到是否有人切到旁观视角。
- 战场是可调高度的网格画布，卡牌可重叠摆放，放置时会吸附到网格点。
- 战场支持同步标记：可以添加文本、颜色和内置符号标记，标记可拖动，右键可删除。
- 可以把自己的牌拖到战场任意网格位置，或拖到手牌、墓地、放逐区、牌库；拖到牌库时会选择牌库顶、牌库底或洗入牌库，程序不判定是否合法。
- 牌库、额外牌组、墓地、放逐区位于手牌栏右侧的单行区域，每个区域占一张手牌大小，可以点击展开；牌库和额外牌组按种类展示，墓地和放逐区按放入顺序展示。
- 墓地和放逐区可以拖出后再选择具体牌移动；额外牌组由牌表 `EXTRA` 段导入，只按种类记录，不记录数量，拖到战场时会先放置卡背，再选择要放出的牌。
- 对手手牌只显示背面和数量。
- 手牌和战场上的牌显示完整卡面。
- 生命和法术力池由程序维护。
- 抓牌、上场、入墓、放逐、回手、回库、横置、重置等自由操作。
- 支持按牌名创建衍生物，并通过 Scryfall API 查询衍生物卡图；创建过的衍生物会登记到额外牌组，后续可从额外牌组再次创建。
- 支持导入牌表，格式示例：

```text
4 Lightning Bolt
8 Island
2 Snapcaster Mage

EXTRA
Treasure Token
Insectile Aberration

SB: 2 Negate
```

导入时会忽略 `Sideboard` 区块和 `SB:` 备牌行；主牌支持 `4 Card Name` 和 `4x Card Name` 数量写法；`EXTRA` 段中的数量会被忽略，只保留卡名种类。程序会在浏览器中直接调用 Scryfall API 查询英文牌图，并直接加载 `cards.scryfall.io` 图片；不再依赖本地后端卡图代理、dragonbox 或本地图片目录。法术力和战场标记符号使用 Scryfall 的符号 SVG。无法联网或找不到牌时，会显示简化占位卡面。

如果部署到纯静态平台，卡图查询仍可工作，因为它不依赖 `server.py`。但大厅、创建牌桌、加入牌桌和线上同步仍需要 `server.py` 提供 `/api/tables`、`/api/tables/join`、`/api/table/state` 等后端接口；只上传到静态托管时，跨设备同步不会生效。

## 后续建议

当前联机方式是多牌桌 HTTP 自动同步：

- 客户端创建或加入牌桌后，后续请求都会携带牌桌号和本机连接 ID。
- 客户端操作后 POST 整张牌桌状态到 `/api/table/state`。
- 客户端每秒 GET `/api/table/state` 拉取当前牌桌的最新状态；请求会携带本地 `updatedAt`，如果服务端状态没有更新，只返回轻量的 `{ "unchanged": true }`。
- 客户端上传状态失败时会保留待上传标记，并在后续自动重试。
- 客户端定期向 `/api/table/heartbeat` 发送心跳，离开页面时向 `/api/table/leave` 报告退出。
- 服务端只在内存中保存牌桌状态，重启服务会清空线上牌桌。
- 不区分玩家身份，不做合法性或作弊校验。
